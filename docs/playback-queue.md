# Воспроизведение и очередь по модели Spotify

Исследование от 7 октября 2026 года. Документ фиксирует поведение Spotify и
предлагает модель для Pookie. Перестройка системы воспроизведения ещё не реализована.

## Подтверждённые правила Spotify

- Источник воспроизведения — альбом, артист или плейлист; запуск может происходить
  с заданного трека внутри источника. Это отдельное понятие от списка конкретных
  треков. [Start/Resume Playback](https://developer.spotify.com/documentation/web-api/reference/start-a-users-playback).
- В очереди разделены текущий трек, вручную добавленные позиции, продолжение
  источника и рекомендации. Ручные позиции имеют приоритет перед продолжением
  источника. Очистка удаляет ручные позиции. Запуск отдельного трека из поиска
  создаёт очередь из одного трека. Без Autoplay и Repeat воспроизведение в конце
  заканчивается. [Spotify Queue FAQ](https://community.spotify.com/forum/en/kb/articles/807-how-does-the-play-queue-work).
- Можно добавлять, удалять и переставлять позиции очереди.
  [Play Queue](https://support.spotify.com/article/play-queue/).
- Повтор имеет три режима: выключен, источник целиком, текущий трек.
  [Set Repeat Mode](https://developer.spotify.com/documentation/web-api/reference/set-repeat-mode-on-users-playback).
- Shuffle сохраняет построенную последовательность при выборе другого трека;
  в актуальном Spotify есть Standard и Fewer Repeats, учитывающий недавнее
  прослушивание. [Обновление Shuffle](https://newsroom.spotify.com/2025-11-13/shuffle-update-fewer-repeats/).
- Smart Shuffle добавляет подходящие рекомендации внутрь подборки; Autoplay
  продолжает похожими треками после окончания источника. Это разные функции.
  [Shuffle](https://support.spotify.com/article/shuffle-play/),
  [Autoplay](https://support.spotify.com/article/autoplay/).

Документация описывает поведение, но не раскрывает внутреннюю модель данных и
точные алгоритмы рекомендаций Spotify. Дальше — проектирование для Pookie.

## Что сейчас отличается в Pookie

| Участок | Текущее поведение | Требуемое изменение |
| --- | --- | --- |
| `SetQueue` | Копирует `tracks` с открытой страницы | Создавать независимый источник с идентификатором и курсором загрузки |
| `SkipAsync` | Следующий индекс считается по модулю длины | Завершать источник при выключенном повторе |
| Shuffle | Следующий трек выбирается из `shuffleBag` | Строить стабильную последовательность, которую показывает и использует плеер |
| Полноэкранная очередь | Вычисляется как хвост исходного `queueTracks` | Показывать реальный порядок следующих позиций, включая Shuffle |
| Предыдущие строки | Включают весь префикс исходного списка | Показывать фактическую историю воспроизведения |
| Ручная очередь | Отдельной модели нет | Приоритетный редактируемый список перед продолжением источника |
| Поиск | Запуск включает остальные загруженные результаты | Отдельный результат запускать как одиночный источник |
| Пагинация | Очередь содержит только уже загруженные позиции | Догружать источник независимо от текущей страницы |

Основные участки: `MainWindow.Navigation.cs`, `MainWindow.cs`,
`MainWindow.ExpandedQueue.cs`, `MainWindow.Library.cs` и `MainWindow.MediaSession.cs`.

## Предлагаемая модель

Отделить `PlaybackQueue` от UI и загрузки аудио. Его снимок содержит:

- `Context`: тип, идентификатор, название, исходный порядок, курсор следующей страницы.
- `Current`: конкретное вхождение трека, источник и состояние подготовки аудио.
- `ManualUpcoming`: вручную добавленные позиции в выбранном пользователем порядке.
- `ContextUpcoming`: оставшаяся последовательность источника, обычная или перемешанная.
- `History` и `Forward`: фактические переходы назад и вперёд.
- `RepeatMode` и `ShuffleMode`: независимые режимы.

Каждой позиции нужен собственный `EntryId`: один трек может встречаться несколько
раз. Использование `track.Id` как ключа позиции теряет такие повторения и ломает
удаление, перемещение и подсветку отдельных вхождений.

Все представления очереди, кнопки плеера и системные медиакоманды используют один
снимок модели. UI не вычисляет следующий трек самостоятельно.

## Переходы и загрузка

1. `StartContext` фиксирует источник; переход между страницами его не меняет.
2. `Enqueue` добавляет позицию в конец ручной очереди, `PlayNext` — в её начало.
3. `Next` выбирает ручную позицию, затем продолжение источника. Возврат к источнику
   сохраняет его курсор. Повтор трека применяется при естественном завершении;
   ручная команда Next должна позволять перейти дальше.
4. `Previous` после порога позиции возвращает текущий трек к началу; до порога
   идёт по реальной истории. Порог 3 секунды — предлагаемый выбор Pookie.
5. Shuffle перестраивает оставшийся порядок при включении, а выбор позиции внутри
   него сохраняет остальные позиции. Ручная очередь сохраняет свой порядок.
6. Изменение UI-трека происходит сразу. Подготовка потока выполняется отдельно;
   отменённый старый запрос не может заменить текущий трек или снимок очереди.
7. Курсор источника догружается заранее перед исчерпанием остатка: один запрос
   одновременно, отмена при замене источника, устойчивые ключи позиций.

## Проверки при реализации

Проверить приоритет ручных позиций и возврат к источнику, дубликаты треков,
перестановку/удаление, историю назад-вперёд, сохранение Shuffle, конец источника
при каждом Repeat, пагинацию и отмену устаревшей загрузки. Отдельно проверить
совпадение показанного порядка с фактическими переходами и системными командами.

Рекомендации Smart Shuffle и Autoplay потребуют доступного источника похожих
треков SoundCloud. Их следует подключать к этой модели отдельно от обычной очереди.
